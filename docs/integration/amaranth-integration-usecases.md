# 아마란스 연계 — PMS 유스케이스 정리 및 스키마 초안 공유 요청

> **목적**: 아마란스 연계 협의를 위해, PMS에서 아마란스 정보가 필요한
> **화면·시점·용도**와 각 경우에 필요한 **최소 정보**를 정리한 문서.
> API의 형태·제공 방식은 아마란스 측 설계에 따르며, PMS는 **응답 데이터 형태
> 초안(§3)을 공유받아** 그에 맞춰 설계를 병행하고자 한다. 제공이 어려운 항목은
> PMS 쪽에서 다른 방식으로 풀 수 있는 경우 그 대안을 함께 적어두었다.
>
> 작성일: 2026-07-06 / 작성: AetherPMS 개발팀

---

## 1. 전제 — PMS의 개인정보 취급 원칙

연계 범위를 판단하실 때 도움이 되도록, PMS가 지키는 원칙을 먼저 밝힌다.

1. **저장하지 않는다** — 내부 인력의 상세정보(부서·직급·재직상태 등)는 PMS DB에
   저장하지 않고 **화면 표시 시점에 조회**만 한다. PMS가 보관하는 것은
   **사번 + 이름 스냅샷**(목록 표시용)뿐이다.
2. **외부 인력은 조회 대상이 아니다** — 외주·협력사 인력은 아마란스에 없으므로
   PMS가 자체 관리하며, 연계 API 호출 대상이 아니다.
3. **외부 인력 계정은 아마란스 데이터에 접근할 수 없다** — 계정 유형(INTERNAL/EXTERNAL)
   기반으로 앱 계층과 DB 정책에서 차단한다. 연계 API 호출은 내부 인력 컨텍스트에서만 발생한다.
4. **필요 정보는 유스케이스별 최소 집합만** — 아래에 명시한 항목 외의 개인정보
   (생년월일, 개인 연락처, 주소 등)는 필요하지 않다.

## 2. 유스케이스별 필요 정보

### 2.1 내부 직원 로그인

- **시점**: 내부 직원이 PMS에 로그인할 때
- **필요한 것**: 아마란스 계정으로 인증을 위임하고, 인증 결과로 **사번과 이름**을 받는 것
- PMS는 내부 인력의 비밀번호를 보유하지 않는 것이 원칙
- 인증 연동 방식(OIDC 등)은 아마란스 환경에 맞춰 협의

### 2.2 프로젝트 멤버 지정 — 사용자 검색

- **화면**: 프로젝트 참여인력 등록 시, 이름이나 부서로 검색해서 대상자를 선택
- **필요한 최소 정보**: 사번, 이름, 부서명 (직급/직책이 있으면 목록 표시에 활용)
- **희망하는 검색 형태**:
  - 검색 조건: **이름(부분 일치), 부서, 사번 직접 입력** — 이 셋 중 이름 검색이 핵심
  - 결과에 **동명이인을 구분할 수 있는 정보**(부서명·직급) 포함
  - 재직자만 나오는 것이 기본이면 충분 (퇴직자 검색은 불필요)
- 검색 제공이 어렵다면 **조직도 탐색(부서 → 소속원)** 방식으로도 구현 가능

### 2.3 인력 정보 표시

- **화면**: 프로젝트 멤버 상세, 담당자 표시 등에서 사번으로 조회
- **필요한 최소 정보**: 이름, 부서명, 직급/직책, 재직상태
- **필요하지 않은 정보**: 생년월일, 개인 연락처, 주소
- **희망 형태**: 멤버 목록 화면에서 여러 명을 한 번에 표시하므로,
  단건 조회 외에 **사번 여러 개를 한 번에 조회**할 수 있으면 호출 횟수를 크게 줄일 수 있다
- 회사 이메일은 PMS 알림 발송 용도로 검토 중 — 제공이 어렵다면
  아마란스 쪽 알림 기능을 활용하는 등의 대안으로 협의 가능

### 2.4 재직 여부 확인

- **용도**: 퇴직자의 PMS 계정 자동 비활성 처리
- **필요한 정보**: 사번 기준 재직 여부만

### 2.5 전자결재

- **역할 분담**: 승인/반려 **실행은 아마란스 전자결재에서** 한다.
  PMS는 결재요청을 만들고, 상태와 이력을 표시하는 것까지만 한다.
- **필요한 것**:
  - 결재 기안 생성(기안자 사번, 제목, 내용) → 결재건 식별자를 PMS가 보관
  - 결재건의 상태(기안/결재중/완료/반려)·현재 결재자·처리 이력 조회
  - 결재라인 표시 시 **각 관여자의 역할 구분(결재/합의/참조)** 정보
- **조회 권한을 어떻게 볼지가 핵심 협의 포인트**:
  - PMS 화면에서는 결재건이 프로젝트에 연결되어 표시되는데,
    **진행 중인 결재를 아무에게나 보여줄 수는 없다**는 점을 PMS도 동일하게 인식
  - 조회 요청자(사번)를 함께 전달할 테니, 아마란스 권한 기준
    (기안자·결재자·합의자·참조자 여부)으로 **조회 가능 여부 또는 노출 수준을
    판단해서 응답**해주는 형태를 희망
  - 예: 관여자가 아니면 제목·상태 수준만, 관여자면 결재라인·이력까지 — 와 같은
    단계적 노출도 좋음. 어느 선이 가능한지 협의 필요
- 상태 변경을 즉시 알 수 있는 방법(webhook 등)이 있으면 좋지만, 없으면 주기적 조회로 처리
- 기안 생성 연계가 어렵다면, **아마란스 기안 화면으로 이동(딥링크)** 후
  결재건을 PMS에 연결하는 방식으로도 구현 가능

### 2.6 근태/가용 조회

- **화면**: 프로젝트 투입 인력의 일자별 가용 여부 표시(자원 투입 계획)
- **필요한 정보**: 사번 + 기간 → **일자별 가용/부재 여부만**
- **휴가 유형·사유는 필요하지 않다** — "부재" 단일 값이면 충분
- **조회 권한 협의 포인트**: 본인이 아닌 **타인의 근태를 조회하는 시나리오**
  (PM이 자기 프로젝트 투입 인력의 가용을 확인)라는 점이 핵심
  - 아마란스의 기존 권한 모델(예: 부서장이 부서원 조회)과 PMS의 조회 범위
    (프로젝트 단위, 부서 무관)가 다를 수 있음
  - 희망: 조회 요청자와 대상자를 함께 전달하면 아마란스가 허용 여부를 판단하거나,
    혹은 "가용/부재 여부만"이라는 낮은 민감도를 감안해 내부 인력 간에는
    허용하는 정책 — 어느 쪽이 가능한지 협의 필요

### 2.7 파일(원챔버)

- **용도**: 산출물/첨부를 원챔버에 저장하고 PMS는 **문서 식별자만 보관**
- **필요한 것**: 업로드, 메타 조회(파일명·크기), 다운로드 또는 열람 링크
- **용량·정책 협의 포인트**: PMS는 **산출물 버전 이력 관리**를 하려는 중이라,
  산출물이 수정될 때마다 덮어쓰기가 아니라 **새 버전 파일이 누적**된다
  - 이런 누적 업로드가 원챔버 정책·용량상 괜찮은지
  - 파일당/전체 업로드 용량 제한이 있는지
  - 원챔버 자체에 버전 관리 기능이 있다면 그걸 활용할지,
    PMS가 버전별 문서 식별자를 각각 보관할지
- 연계가 어렵거나 용량 정책상 부담이 된다면 **PMS 자체 스토리지로 대체**하는
  분기가 이미 있으므로, 방향만 정해지면 된다

## 3. 먼저 공유를 부탁드리는 것 — 응답 데이터 형태 초안

API가 확정되기 전이라도, **응답 데이터의 필드 구성 초안(샘플 수준이면 충분)** 을
먼저 공유해주시면 PMS 쪽 설계를 병행할 수 있다. 이후 설계가 바뀌면 PMS가 맞추면
되므로, 확정본이 아니어도 된다.

특히 아래 두 가지는 PMS 내부 설계가 응답 형태에 직접 걸려 있어 우선 공유를 희망한다:

1. **사용자 정보 조회 응답** (2.2, 2.3) — 어떤 필드가 어떤 이름·형태로 오는지에 따라
   PMS의 계정 연결·권한 설계가 달라짐. 재직상태의 값 체계(재직/휴직/퇴직 등)도 포함되면 좋음
2. **전자결재 상태 조회 응답** (2.5) — 상태 값 체계와 결재라인 구조(역할 구분 포함)에 따라
   PMS의 상태 캐시·표시 설계가 달라짐

## 4. 협의하면 좋을 사항 (미팅 안건)

문서 회신보다는 미팅에서 논의하는 것이 효율적인 항목들:

- 각 유스케이스에 적어둔 **권한·정책 협의 포인트**
  (2.5 결재 조회 권한, 2.6 근태 조회 권한, 2.7 원챔버 용량·버전 정책)
- 서버 간 인증 방식과, 조회를 일으킨 사용자 컨텍스트 전달 방식(감사로그 목적)
- 식별자 체계 — 사번을 그대로 쓸지, 별도 ID를 발급할지
- 표시 필드 마스킹 정책 (마스킹 범위에 따라 화면 사용성 협의 필요)
- 개발/테스트 환경과 테스트 계정
- 아마란스 점검/장애 시 PMS 동작 (이름 스냅샷으로 대체 표시 예정)

## 5. 협의 이후 PMS 측 후속

- 협의 결과를 전제로 연계 설계 확정 → `docs/design/0005`(인증 이원화) 등 설계 문서에 반영
- 제공 범위에 따라 `UserPort`/`ApprovalPort`/`AttendancePort`/`FilePort` 인터페이스 확정
- 파일(2.7) 미연계 시 PMS 자체 스토리지 설계로 분기
