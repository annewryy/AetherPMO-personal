# 요구 0004 — RBAC 권한 체계(확정) + UI 조정 3건

- **접수**: 2026-07-24 너울님 (구 Aether PMS에서 최종 정리했던 체계 재확정)
- **상태**: 접수 → 설계 대기 (RBAC는 0005 자체 로그인/identity 설계와 통합 필요)

## 1. RBAC — 역할 5종 (확정)

역할 축은 5개만 사용: **SYS_ADMIN / EXEC_ADMIN / PM / WORKER / VIEWER** (구 체계의 public.profiles.role 상당 — 우리 스키마에선 pms_user.role로 수용 예정).

| 역할 | 정의 |
|---|---|
| SYS_ADMIN | 시스템 전체 관리 — 사용자·권한 관리, OPMS 방법론 CRUD, 모든 프로젝트·산출물 접근 |
| EXEC_ADMIN | 사업관리 총괄 — 전체 프로젝트 관리, 인력관리, 공문, 보고서. 방법론은 조회만 |
| PM | 자신이 참여한 프로젝트 관리 — 액션아이템·회의록·리스크·산출물 작성, 프로젝트 멤버 관리 |
| WORKER | 자신에게 배정된 업무 수행 — 담당 액션아이템 수정, 담당 산출물 작성, 프로젝트 정보 조회 |
| VIEWER | 읽기 전용 — 수정·삭제 불가 |

| 기능 | SYS_ADMIN | EXEC_ADMIN | PM | WORKER | VIEWER |
|---|---|---|---|---|---|
| 방법론 조회 | ✅ | ✅ | ✅ | ✕ | ✕ |
| Template 생성 / Stage·Activity·Artifact 수정 / Project Type 관리 | ✅ | ✕ | ✕ | ✕ | ✕ |

→ **방법론 마스터는 SYS_ADMIN만 수정 가능** (검증 스크립트도 이 기준: SYS_ADMIN만 마스터 쓰기 성공해야 함).

## 2. UI 조정 3건

1. **입찰→수행 전환 버튼**: 입찰단계 프로젝트 상세에 전환 버튼 신설 — 기존 lineage 설계(0001, sourceProjectId·-B 발번)를 실행하는 UI. 전환 조건(수주 상태 등)·복제 범위는 설계에서 확정.
2. **용어 통일**: "카탈로그" → **"테일러링"** (메뉴·화면 라벨 전반). 방법론 문서 체계(테일러링 가이드)와 용어 정합.
3. **메뉴 재배치**: 이슈/리스크·액션아이템·공문·회의록(전사 현황 그룹) → **"프로젝트" 하위 메뉴로 전환**. 유경님 메뉴 트리(이슈/Action/공문/회의록 관리)와 우리 프로젝트 중심 구조의 절충 — 상세 배치는 설계에서 확정.
