## 1. 인력 관리 메뉴 고도화 (인력 마스터 테이블 구축)

### 배경 / 목적

현재는 프로젝트별로 참여인력이 개별 등록되어 인력이 중복 저장된다. 이를 **하나의 인력 마스터**로 통합 관리하여 프로젝트 간 중복 등록을 방지하고, 인력 현황을 전사 기준으로 통합 조회할 수 있도록 한다.

### 1-1. 데이터 동기화 로직

**트리거 시점**: 프로젝트 관리 → 수행단계에서 참여인력 저장 시

**처리 순서**:

1. `resources` 테이블에서 동일 인력 존재 여부 조회
   - 조회 기준: `name` + `employment_type`
2. 분기 처리
   - 존재하는 경우 → 기존 `resources.id` 재사용
   - 존재하지 않는 경우 → `resources`에 신규 Insert
3. `project_members.resource_id`에 위에서 확정된 `resources.id` 연결(FK)

```text
[참여인력 저장]
      │
      ▼
resources 조회 (name + employment_type)
      │
   ┌──┴──┐
 존재함   존재안함
   │         │
기존 id    신규 Insert
   │         │
   └────┬────┘
        ▼
project_members.resource_id 연결
```

### 1-2. 프로젝트 삭제 시 처리

- `project_members` 데이터만 삭제
- `resources`(인력 마스터)는 **삭제하지 않음** → 인력 마스터 데이터 유지

> ⚠️ 개발 시 주의: 프로젝트 삭제 로직에 `resources`까지 함께 삭제하는 cascade가 걸려있지 않은지 반드시 확인.

### 1-3. 신규 메뉴: 인력관리

- **조회 대상**: `resources`
- **조회 필터**: 인력구분 체크박스(복수선택 가능)
  - [ ] 정규직
  - [ ] 자사화
  - [ ] 프로젝트 계약직
  - [ ] 외주(턴키)
  - [ ] 프리랜서
  - 복수선택 시 AND/OR 조건 선택 가능(기본값: OR)
    - 예: "정규직 + 자사화" 선택 시 → 두 유형만 조회
- **검색 조건**
  - 이름
  - 소속회사
  - 현재 투입 프로젝트
  - 수행장소
  - 고객사

### 1-4. Supabase 테이블 스키마

**`resources`** (인력 마스터, 신규)

| 컬럼 | 설명 |
|---|---|
| `id` | UUID (PK) |
| `name` | 성명 |
| `employment_type` | 정규직 / 자사화 / 프로젝트 계약직 / 외주 |
| `company` | 소속회사 |
| `phone` | 연락처 |
| `email` | 이메일 |
| `department` | 부서 |
| `position` | 직책 |
| `status` | 재직/종료 |
| `created_at` | 생성일 |

**`project_members`** (기존 테이블 + 컬럼 추가)

| 컬럼 | 설명 |
|---|---|
| `resource_id` | `resources.id` 참조 FK (신규 추가) |

###1-5. 인력 상세 및 프로젝트 이력 조회
**배경 / 목적**

인력관리 메뉴는 단순한 인력 목록 조회를 넘어, 인력별 프로젝트 수행 이력을 통합 관리할 수 있도록 개선한다. 이를 통해 인력의 수행 경험과 역할을 한눈에 확인할 수 있으며, 향후 프로젝트 인력 배치 및 PM 선정 시 참고 자료로 활용할 수 있다.

**인력 상세 화면**

인력 목록에서 특정 인력을 선택하면 인력 상세 화면으로 이동하며, 기본 인적 정보와 함께 프로젝트 참여 이력을 조회할 수 있도록 구성한다.

**기본 정보**

성명
소속회사
고용구분
부서
직책
연락처
이메일
재직상태
프로젝트 참여 이력

해당 인력이 지금까지 참여한 모든 프로젝트를 시간순으로 조회할 수 있도록 한다.

**조회 항목 예시**

프로젝트	기간	고객사	역할	수행장소	상태
2025년 제2차 정보자원 통합구축 HW2	2025.08 ~ 2026.08	국가정보자원관리원	PM	대전	완료
2026년 국가정보자원관리원 대구센터 운영	2026.01 ~ 2026.12	국가정보자원관리원	PM	대구	수행중
차세대 ISP 사업	2027.03 ~ 2027.09	○○기관	PL	서울	예정
데이터 조회 방식

프로젝트 참여 이력은 아래 테이블을 기준으로 조회한다.

resources
    ↓
project_members
    ↓
projects

resources.id와 project_members.resource_id를 기준으로 JOIN하여 해당 인력이 참여한 프로젝트 목록을 조회하며, 프로젝트의 역할(Role), 수행기간, 수행장소, 진행상태 등의 정보를 함께 표시한다.

**기대 효과**
인력별 프로젝트 수행 이력을 통합 관리하여 업무 이력 조회 편의성 향상
프로젝트 배치 시 유사 수행 경험을 가진 인력을 빠르게 확인 가능
PM, PL 등 핵심 역할 수행 이력을 기반으로 인력 선정 지원
향후 인력 역량 분석, 프로젝트 투입 이력 관리, 통계 기능으로 확장 가능한 기반 마련


## 2. 프로젝트 관리 > 수행단계 화면 개선

### 배경 / 목적

프로젝트 수 증가에 따라 사용자가 목록을 카드형/리스트형 중 원하는 형태로 선택할 수 있도록 개선한다.

### 2-1. 보기 방식 토글

- 상단에 Toggle 추가
  - [ ] 카드형 (기본값, 현재 UI 유지)
  - [ ] 리스트형 (테이블 형태)

**리스트형 컬럼 예시**

| 사업번호 | 사업명 | PM | 고객사 | 수행장소 | 진척률 | 상태 |
|---|---|---|---|---|---|---|

### 2-2. 수행장소 필터 추가

- 기존 필터 외 **수행장소(location)** 필터 추가
- 조회 항목: 서울 / 대전 / 대구 / 광주 / 기타

**DB 관련**

- `projects` 테이블 기존 컬럼 사용
- 컬럼명이 `location` 또는 `site_location`으로 혼재되어 있다면 **하나로 통일 권장**

## 3. 입찰단계 > 나라장터 공고조회 개선

### 배경 / 목적

실제 영업 대상기관 중심으로 빠르게 조회할 수 있도록 개선한다.

### 3-1. 검색조건: 기관 선택 Dropdown

- 기존 자유검색 → **기관 선택 Dropdown**으로 변경
- 기본 항목
  1. 국가정보자원관리원
  2. 한국지역정보개발원
  3. 한국지능정보사회진흥원
  4. 직접입력 (선택 시 텍스트박스 활성화)

**권장 사항**: 향후 관리 편의를 위해 하드코딩 대신 마스터 테이블(`bid_target_agencies`)로 관리

```text
bid_target_agencies
├─ id
├─ agency_name
├─ sort_order
└─ is_default
```

### 3-2. 공고 유형 분리 조회

- 기존: 본공고만 조회
- 변경: 아래 3가지 옵션으로 조회
  - ○ 전체
  - ○ 사전규격
  - ○ 본공고
- API 호출 시 나라장터 OpenAPI의 공고 유형 값을 활용하여 결과 구분
- 결과 Grid에 **공고유형 컬럼 추가**, Badge 형태로 표시

**결과 Grid 예시**

| 공고번호 | 공고유형 | 공고명 | 기관 | 공고일 | 마감일 |
|---|---|---|---|---|---|

- 공고유형 Badge: `사전규격` / `본공고`

## 개발 시 공통 고려사항

### 데이터 정합성

- 참여인력은 반드시 `resources`를 기준으로 관리
- `project_members`는 프로젝트-인력 간 매핑(관계) 정보만 관리
- 프로젝트 삭제 시에도 인력 마스터(`resources`)는 유지

### UI/UX

- 프로젝트 화면은 카드형 ↔ 리스트형 즉시 전환 가능하도록 구현
- 모든 조회 필터는 **클라이언트 사이드 필터링이 아닌 DB 조건(Query) 기반**으로 처리
- 나라장터 조회는 API 재호출 없이, 조회 결과 캐시를 활용하여 검색/필터링 수행

---

## 기대 효과

- 인력 정보를 프로젝트 단위가 아닌 **전사 마스터 기준**으로 관리하여 중복 데이터 최소화
- 프로젝트 증가 시 카드형/리스트형 병행 제공으로 가독성 및 운영 효율 향상
- 실제 영업 대상기관 중심의 빠른 입찰 공고 조회 지원
- 사전규격공고와 본공고를 구분하여 입찰 준비 시점을 앞당기고 선제적 사업 대응 가능
