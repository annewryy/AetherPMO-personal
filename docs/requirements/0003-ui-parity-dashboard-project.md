# UI 파리티 — 대시보드·프로젝트관리 (유경님 UI 기준 갭 + 결정사항)

> 레거시(`/`, 유경님) UI와 우리 `/app`의 차이를 **프로젝트관리 단계까지** 비교 분석하고,
> 너울님 결정(2026-07-24)을 반영해 구현 범위를 확정한 문서.
> 분석 근거: 루트 `index.html`/`app.js`(레거시) vs `web/src`(우리) 코드 대조.

- **작성**: 너울님 팀 · 2026-07-24
- **관련**: [design/0024](../design/0024-legacy-parity-schema.md) §B (레거시 파리티 갭) · [requirements/0002](0002-parity-features-clarification.md) (급여·게시판·체크리스트 — 별도 트랙)
- **상태**: 범위 확정 → 설계/구현 대기

## 0. 결정사항 (2026-07-24, 너울님)

1. **AI First Portal 미채택.** 더미 챗봇(AI 브리핑 콘솔)은 지금 구현 가능한 내용이 아니므로 제외.
   단, 우측 3개 위젯 — **"오늘 가장 주의가 필요한 프로젝트"·"주요 리스크"·"지금 실행하면 좋은 조치"** — 는
   AI가 아니라 **설정한 기준(규칙 기반)** 으로 산출해 우리 대시보드에 채택.
   → 기존 신호 규칙 엔진(`pms_signal_rule` + 관리자 콘솔 > 신호 규칙)을 확장하는 방향.
2. **입찰단계 목록의 나라장터 분할 패널 미채택.** 레거시는 입찰 탭 우측에 나라장터 공고조회를 내장하지만,
   나라장터 공고조회 메뉴가 별도로 있으므로 중복 — 입찰단계 목록은 단일 목록으로 구현.
3. **인력관리는 우리 것 유지.** 하위는 **참여인력 관리까지만** 우선 구현. 계약 관리·월급여 관리는 보류(0002 트랙: 계약=유경님 구현 안정화 대기, 급여=엑셀 파일 대기).
4. **외주인력 소속회사 저장** (2026-07-24 추가): 인력 정보 입력 시 외주(비자사) 인력은 **소속회사를 함께 저장**할 수 있어야 함.
   - 현황: 스키마·API는 이미 지원(`pms_person.company_id` → `pms_company` FK, MemberService `companyId` 수용). 참여인력 폼엔 자유 텍스트 "소속"만 존재.
   - 작업: 폼의 소속을 **회사 기준정보(pms_company) 선택**으로 전환(신규 회사 즉석 등록 허용), 고용형태가 외주 계열(insourced 전 외주/턴키/프리랜서/프로젝트계약)일 때 **입력 필수화**. 인력관리(전사) 등록·수정 폼에도 동일 적용.

## 1. 메뉴 구조 (결정 반영)

**목표 구조** (레거시 기준 + 결정 반영):

```
대시보드
프로젝트 관리 ▾
  ├ 입찰단계
  ├ 수행단계
  └ 나라장터 공고조회        ← 현 "입찰 > 나라장터 공고조회"를 하위로 이동
템플릿 ▾ (카탈로그 / 산출물 검색)   ← 유지(레거시 "산출물 템플릿 관리"의 단계별 분류 축은 채택 안 함)
전사 현황 ▾ (이슈/리스크 · 액션아이템 · 공문 · 회의록 · 인력관리)  ← 유지
관리자 ▾                    ← 유지
```

- 현 "프로젝트" 단일 메뉴 → "프로젝트 관리" 상위 + 하위 2단계 목록(입찰/수행)으로 분리.
  라우트는 `/projects?stage=` 쿼리 또는 `/projects/bidding`·`/projects/active` 방식 — 설계에서 확정.
- 게시판: 0002 트랙(요구 확인 대기). 시스템 설정(백업): 미채택(관리자 콘솔 유지).

## 4. 입찰 프로젝트 상세 갭

**헤더**: 레거시 = 상태·D-Day·위험도 배지 + KPI 6카드(고객사/PM/사업기간/계약금액/사업상태/진척률) + 삭제 버튼. 우리 = 이름+배지+수정. → **KPI 카드·D-Day 추가**, 삭제는 정책 확인 후.

**탭**: 레거시 입찰 = 사업개요/제안준비서류/컨소시엄/VRB. 우리 = 개요/제안 태스크/WBS·일정/컨소시엄/VRB/참여인력/활동로그.
→ "제안 태스크" 라벨을 **"제안준비서류"** 로 맞출지 설계에서 확정. 참여인력·활동로그 탭은 유지(개요에 요약 카드 추가).

**사업개요 탭 — 6섹션 (2행×3열)**:

| # | 섹션 | 레거시 필드 | 우리 현황 | 작업 |
|---|---|---|---|---|
| O1 | 기본정보 | 사업명/코드/**공고번호/발주기관/사업예산**/사업유형/**제안서 제출마감일**/비고(입력·저장) | dl 있음, 입찰 특화 필드 없음 | 입찰 분기 필드 추가 |
| O2 | 담당조직 정보 (입찰 전용) | 영업/제안전략팀/제안PM/사업관리/계약/법무 담당자 | 없음 (**DB 필드도 없음**) | 스키마+API+UI 신규. 수행단계는 기존 "프로세스별 진척률" 유지 |
| O3 | 참여인력 요약 | 아바타+고용형태 배지, 투입 N(총 M), 제외 포함 토글 | 별도 탭에만 존재 | 개요에 요약 카드 추가 |
| O4 | 주요일정 | WBS 단계 세로 타임라인(진척률·가중치) | WBS/일정 별도 탭에만 | 개요에 요약 카드 추가 |
| O5 | 최근활동 | 해당 프로젝트 활동 4건 | 활동로그 별도 탭에만 | 개요에 요약 카드 추가 |
| O6 | 연관정보 | 산출물/회의록/리스크/액션/공문 건수 배지 → 탭 이동 | 없음 | 추가. **명칭 변경 검토**(예: "현황 요약") |

## 5. 구현 배치 제안 (설계 → impl 순)

1. **B1 메뉴·목록 개편**: §1 메뉴 구조 + §3 L1~L4 (스키마 불필요, 프론트 중심 + 목록 API 필드 보강)
2. **B2 대시보드**: D1·D2 (기존 데이터로 가능) → D3~D5 (신호 규칙 확장 설계 필요)
3. **B3 입찰 상세 사업개요**: O1·O3~O6 (기존 데이터 재배치) + O2 (스키마 작업 포함)
4. 헤더 KPI 카드·라벨 정리는 B3에 포함

각 배치는 design/00NN 문서 → impl/* 브랜치 → dev 검증(스크린샷) → 확인 후 main 병합 순서를 따른다.
