# 프로젝트 목록(수행단계) 화면 개선

유경님 요구(`docs/requirements/0001` §2)를 반영. 규모 증가 대응 — 보기 방식 선택 + 수행장소 필터.

## 결정 (2026-07-09)

- **컬럼명 혼재 없음**: 제품 스키마는 `pms_project.location` 단일 컬럼(레거시의 location/site_location
  혼재는 제품에 해당 없음 — 유경님 §2-2 통일 요구는 제품에선 이미 충족).
- **모든 필터 서버측 DB 쿼리**(유경님 공통 고려사항). 현행 `GET /api/projects`는 전체 반환이라 **필터
  파라미터 신설**이 백엔드 델타.

## A. 보기 방식 토글 (프론트 — `/app` Vue)

- 상단 토글: **카드형(기본, 현행 UI)** ↔ **리스트형(테이블)**.
- 리스트형 컬럼: 사업번호 · 사업명 · PM · 고객사 · 수행장소 · 진척률 · 상태.
- 순수 UI(impl/0004). 데이터는 기존 `GET /api/projects`(+A/B 필터) 재사용.

## B. 수행장소 필터 + 서버측 필터 계약

- **수행장소(`location`)** 필터: 서울 / 대전 / 대구 / 광주 / 기타.
- 기존 필터(상태 등)와 함께 **서버 쿼리로 처리**.
- **API 확장**: `GET /api/projects?location=&status=...` — 서버가 WHERE로 필터.
  현행 컨트롤러는 `findAllByOrderByProjectIdAsc()`(전체) → 조건부 조회로 확장.
  계약(응답 shape·camelCase)은 불변, 파라미터만 추가.

## 미결 / 후속

- 진척률 목록 노출: 계산 진척(0006/`/progress`)을 목록에서 어떻게 실을지(집계값 vs 저장 `progress_rate`).
- "기타" 장소 정의(정규 5종 외 매핑).
- 리스트형 정렬·페이징.
