## 개인정보 처리 원칙 (2026-07-08 확정 — 데이터 최소화)
내부 직원 개인정보는 **아마란스가 원본**이고 PMS는 **최소만 보관·나머지는 조회만** 한다.
- **PMS 저장(내부 인력)**: **사번 + 이름만.** 부서·직급·재직상태 등 HR 속성은 저장하지 않고
  아마란스 래핑 API로 **런타임 조회**(표시 시점 lookup, 미영속).
- **생년월일·개인연락처·주소 등**: 수집·저장하지 않음(불필요 명시).
- **HR 속성 ≠ 프로젝트 역할**: 부서/직급/재직상태(HR 속성, 내부는 조회만)와, 이 프로젝트에서의
  역할(`participation_role` PM·PL·개발 등, PMS 프로젝트 데이터, 저장 유지)을 구분한다.
- **외주·협력사 인력**: PMS가 **자체 관리**(아마란스 연계 대상 아님). 외부 인력은 아마란스
  소스 데이터 **조회 차단**(앱 가드 + RLS `source` 조건).
- **이력성 스냅샷**: audit_log·comment·deliverable_version의 이름 스냅샷은 시점 고정 기록으로
  유지(이름은 저장 허용). 부서/직급 스냅샷은 저장하지 않음.
- **스키마 반영(0005 정비)**: `pms_project_member.department`는 내부 인력이면 비우고 아마란스
  조회로 대체. 통합 사람 마스터는 `source`(INTERNAL/EXTERNAL) + 내부 `amaranth_emp_no`(사번)
  + `name`만 최소 보유(0010 B-1의 "단일 사람 마스터"를 이 원칙으로 확정).

## 수집된 입력 (미결 — 설계 시 결정)

### 세션 지속성 정책 (2026-07-06, 동료 커밋에서 관찰)
동료 버전(레거시 `/`)은 Supabase Auth 세션을 **sessionStorage**로 전환함
(커밋 `6bb5446` — 브라우저 탭 종료 시 로그아웃되는 정책. 워처 리포트
[2026-07-06.md](reports/2026-07-06.md) §3 참조).

- **현 상태: 미정.** 신규 버전(web/)이 같은 정책을 따를지, localStorage(지속 로그인)로
  갈지, INTERNAL/EXTERNAL별로 다르게 갈지(예: 외부 인력만 세션 한정) 결정하지 않았다.
- 결정 시 고려: 두 프론트(`/`와 `/app`)의 로그인 지속 시간이 다르면 사용자 혼란,
  외부 인력 보안 요건, 아마란스 SSO 세션과의 수명 정합.
