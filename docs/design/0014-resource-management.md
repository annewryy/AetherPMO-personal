# 인력관리 (인력 마스터 조회·상세·이력)

유경님 요구(`docs/requirements/0001` §1-3 인력관리 메뉴 / §1-5 인력 상세·이력)를 설계로 반영한다.
데이터 기반은 0005의 **단일 사람 마스터 `pms_person`**(유경님 `resources` 흡수). 본 문서는 그 위의
**조회 화면·상세·프로젝트 이력**을 다룬다.

## 결정 (2026-07-09)

- 인력관리 = `pms_person`(전사 인력 마스터) 조회 화면. 프로젝트 단위가 아닌 **전사 기준** 통합 조회.
- **모든 필터는 서버측 DB 쿼리 기반**(유경님 공통 고려사항 — 클라이언트 필터링 금지).
- 신원/저장/동기화(마스터 스키마·저장 시 find-or-insert·프로젝트 삭제 시 보존)는 **0005 소관**. 본 문서는
  조회/표시 계약만.

## A. 인력관리 목록

- **조회 대상**: `pms_person`.
- **필터 — 인력구분(`employment_type`)**: 체크박스 복수선택. **AND/OR 선택(기본 OR)**.
  - 구분값: 정규직 / 자사화 / 프로젝트 계약직 / 외주(턴키) / 프리랜서 (0005 B에서 코드값 확정).
  - 예: "정규직 + 자사화" OR → 두 유형만.
- **검색 조건**: 이름 / 소속회사 / 현재 투입 프로젝트 / 수행장소 / 고객사.
  - 수행장소·고객사·투입 프로젝트는 `pms_project_member`→`pms_project` 조인에서 파생
    (`pms_project.location`, `pms_project.customer_name`, 활성 멤버십).
- **응답 컬럼(목록)**: 성명·인력구분·소속회사·부서·직책·재직상태·(현재 투입 프로젝트 수/명).

**API(신규)**: `GET /api/persons`
- 쿼리 파라미터(예): `employmentTypes=정규직,자사화` · `match=or|and` · `name=` · `company=` ·
  `projectId=` · `location=` · `customer=`.
- 서버가 조건을 SQL WHERE/JOIN으로 처리. camelCase DTO 반환(0003 계약).

## B. 인력 상세

인력 목록에서 선택 시 상세 화면.

- **기본 정보**: 성명 · 소속회사 · 고용구분 · 부서 · 직책 · 연락처 · 이메일 · 재직상태
  (`pms_person` 저장값. 내부 인력은 아마란스 동기화로 최신화 — 0005 C).
- **프로젝트 참여 이력**: 해당 인력이 참여한 **모든 프로젝트를 시간순**으로.
  - 조인: `pms_person.person_id = pms_project_member.person_id` → `pms_project`.
  - 표시 항목: 프로젝트명 · 기간(start_date~end_date) · 고객사 · 역할(`participation_role`) ·
    수행장소(`location`) · 상태.

**API(신규)**:
- `GET /api/persons/{id}` — 기본 정보.
- `GET /api/persons/{id}/projects` — 참여 이력(시간순).

## C. 데이터 접근 계약

- 프론트 `dataClient`에 `persons` 조회 메서드 추가(읽기 전용 — 쓰기/동기화는 0005 저장 경로).
- 응답은 도메인 DTO camelCase. 신규 타입은 `web/src/types.ts`에 정의.

## 기대 효과 (유경님 §1-5)

- 인력별 수행 이력 통합 → 이력 조회 편의, 유사 경험 인력 탐색, PM/PL 이력 기반 배치 지원,
  향후 역량 분석·투입 통계 확장 기반.

## 미결 / 후속

- 목록 **페이징·정렬** 기준.
- **권한**: 전사 인력 조회를 누가 볼 수 있는지(role 기반, 0005 인가와 연계).
- "현재 투입 프로젝트" 정의(활성 멤버십 `is_active`/기간 겹침) 확정.
- 인력 등록/수정 UI(마스터 직접 편집)를 인력관리에서 허용할지 — 0005 저장 경로와 정합.
